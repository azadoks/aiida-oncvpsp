# Plan: attributing ONCVPSP failures to their source

Written 2026-10-14. Spans three sibling repositories in `pseudo-opt/code/`:
`pyoncvpsp` (parser), `aiida-oncvpsp` (CalcJob + Parser), `oncvpsp-opt` (surrogate fitting).

## Motivation

`oncvpsp-opt` currently treats pseudization failure as a single global binary label
(`feasible = oncvpsp_exit_status == 0`). Most failures can in fact be traced to one
angular-momentum channel, and often further to either the semilocal (optimize/pspot)
parameters or the Vanderbilt-Kleinman-Bylander (VKB) stage, which also involves the local
potential. Per-channel feasibility labels let the optimizer fit per-ell feasibility
classifiers on the active dims only, as it already does for ghosts.

## ONCVPSP facts the design relies on

- ONCVPSP exits with status 0 on every error (`stop`, no code). Failures must be read from stdout.
- Stdout is stage-ordered. Headers (ONCVPSP 4.0.1):
  1. input echo (`# ATOM AND REFERENCE CONFIGURATION` ...), then `check_data` messages
     (`test_data: ...`, summary `ERROR: test_data found N ERROR; stopping`)
  2. `Reference configufation results` (all-electron reference atom)
  3. `Begin loop to  construct optimized pseudo wave functions`; then, per `l`:
     driver-loop AE solves, the `debl` check, `wellstate` calls, `qroots`, and only then
     `Calculating optimized projector #N` / ` for l=L`. Hence messages from `debl`, `wellstate`
     and `qroots` for channel `l` print *before* the header for `l`, i.e. after the block of
     `l-1` (attribution rule: `l = last_header_l + 1`, or 0 if no header yet).
  4. `Construct Vanderbilt / Kleinmman-Bylander projectors` (`B matrix Hermiticity error, ll=`
     per channel only when nproj >= 2); then the driver solves the valence states in the VKB
     potential with `vp(:, lloc+1)` (`oncvpsp: lschvkbb ERROR n l ierr`). No header marks this
     sub-stage; it is identified from the message itself.
  5. `Model core correction analysis` (modcore/2/3), `Pseudoatom total energy`
  6. `Diagnostic tests using ...` (run_diag), ` Testing for bound ghosts` (run_ghosts)
  7. `Test configuration N` (run_config)
  8. `DATA FOR PLOTTING` (run_plot, run_phsft), `GNUSCRIPT` / `END_GNU`
  9. `Begin PSP_UPF` / `Begin PSPCODE8` (upfout, psp8out)
- Several messages do not print `l` (qroots, pspot, optimize, run_vkb, debl); see the upstream
  PR list at the end.

## Phase 1: pyoncvpsp (message model + attribution)

1. New module `pyoncvpsp/io/output/_messages.py`:
   - `Stage` (StrEnum): `input, ae_reference, semilocal, vkb, vkb_solve, model_core, diagnostics,
     test_config, logder_plot, output, unknown`.
   - `Scope` (StrEnum): `global, ell, ell_and_local, local, model_core, test_config, input`.
   - `Attribution` (StrEnum): `explicit` (ONCVPSP printed `l`), `inferred` (from stage context
     or input), `none`.
   - `OncvpspMessage` dataclass: `name, level, stage, scope, attribution, l, iproj, n, spin_sign,
     config_index, implicated_parameters, groups, subroutine, description, line_numbers,
     context_lines, context_line_numbers`. `as_dict()` is JSON-serializable.
   - `OncvpspFailure` dataclass: `primary` (first error by line), `errors`, `last_stage_reached`,
     `last_l_reached`, `completed`; convenience properties `stage, scope, l, implicated_parameters`.
   - `implicated_parameters` are flattened input keys (`pseudopotentials__rc__1`,
     `local_potential__rcloc`, ...), matching `oncvpsp_opt.optimizer.features` names.
2. `_data.py`: add `stage` (or `None` = infer from context) and `scope` (or `None` = default for
   the stage) to every definition; add `(?P<l>...)`/`(?P<iproj>...)`/`(?P<n>...)` groups wherever
   ONCVPSP prints them; add `check_data` per-field messages (INPUT stage, with `l` when printed);
   add Fortran runtime-error definitions; rename duplicated warning names
   (`first_pswf_has_node` -> `first_pswf_has_node_warning`, `ldiracfb_not_converged` ->
   `runconfig_ldiracfb_not_converged`).
3. `_text.py`: `_parse_errors` keeps named groups; a stage state machine walks the lines once and
   records `(stage, l, iproj, config_index)` context per line; `messages`, `failure`,
   `last_stage_reached` properties; `warnings`/`errors` stay list[dict] (now with extra keys) for
   backward compatibility; `output` gains `failure`, `last_stage_reached`,
   `convergence_profiles`, `ecut_recommended`.
4. Tests: `tests/fixtures/` with one success output and failures generated by the local binary
   (`oncvpsp/build/bin/oncvpsp.x`): pspot node, qroots, debl, check_data, truncated output,
   test-configuration warnings. Regression test asserting every definition has a stage/scope.

## Phase 2: aiida-oncvpsp (store failure details)

1. Parser always attaches `output_parameters`, including on failure, with keys
   `completed, missing_plot_data, last_stage_reached, errors, warnings, failure`
   (`failure` is the serialized `OncvpspFailure` or `None`).
2. Each physical output is built independently; partial outputs are attached on failure.
3. Exit codes: keep 0/301-304/501/502/503 unchanged. New stage-based codes in the 600 range so
   they never collide with the legacy 504-543 per-error-name codes:

   | code | stage         |
   |------|---------------|
   | 610  | input         |
   | 620  | ae_reference  |
   | 630  | semilocal     |
   | 640  | vkb           |
   | 650  | vkb_solve     |
   | 660  | model_core    |
   | 670  | diagnostics   |
   | 680  | test_config   |
   | 690  | logder_plot   |
   | 695  | output        |
   | 699  | unknown stage |

   Multiple errors map to the primary (first) error's stage. `aiida_oncvpsp.exit_codes` exposes
   `STAGE_EXIT_CODES`, `LEGACY_EXIT_CODES` (504-512 of the pinned pyoncvpsp 4f2974c, name and
   stage) and `exit_status_to_stage(status)`, so `oncvpsp-opt` can interpret old and new data
   uniformly. `oncvpsp-opt`'s feasibility label (`exit_status == 0`) is unaffected.
4. Retrieve `_scheduler-stderr.txt` so Fortran runtime crashes can be detected.
5. Pin pyoncvpsp to the new revision; fix README; add pytest with fixture-based parser tests.

## Phase 3: oncvpsp-opt (consume failure details) - follow-up

- Join `output_parameters.failure` into the trials frame as `fail_stage, fail_scope, fail_ell,
  fail_params, fail_attribution`; for legacy rows use `exit_status_to_stage`.
- Labels: `feasible_{ell}` = 1 on success; 0 if `fail_ell == ell` (or scope `ell_and_local`);
  1 for `ell < fail_ell` when the stage is `semilocal` (those channels completed); NaN otherwise.
  `feasible_global` for input/ae/model-core/unknown failures.
- Per-ell feasibility RFCs on the ell's active dims (as `fit_ghost_rfc`) plus a global RFC;
  combined probability `P = prod_ell P_ell * P_global`. Relax `outcome_ell("feasible")` test.
- Record the perturbed ell in extras during by-ell sampling.

## Status (2026-10-14)

Phases 1 and 2 implemented (uncommitted in both repos). Decisions taken during implementation:

- Attribution metadata is kept in `pyoncvpsp/io/output/_attribution.py` (`ATTRIBUTION` table keyed by
  definition name) rather than inside `_data.py`, so the definition schema and names are unchanged and the
  snapshot-based pyoncvpsp test suite (written in parallel by another session) keeps passing. `failure` /
  `last_stage_reached` are parser properties but are not yet added to `parser.output`; do that together
  with a snapshot regeneration (`uv run pytest --update-snapshots`).
- Error messages in a *completed* run (skipped test configuration `lschvkbb_not_converged`, `rxpsh < rc`)
  are not failures: exit status 0, messages stored in `output_parameters["errors"]`. This differs from the
  old behaviour (exit 504/512) and matters when relabelling old rows.
- ONCVPSP numbers test configurations with 0 = reference configuration, so `config_index = k` maps to
  `test_configurations__{k-1}`.
- `OncvpspInput.get_num_ae_bound_states` counted core states; fixed to valence-only (it decides whether
  `ep`/`debl` are active and thus which parameters a failure implicates).
- The Fortran runtime error goes to stderr; the AiiDA parser appends `_scheduler-stderr.txt` to the
  parsed text when it contains a runtime-error marker, and pyoncvpsp attributes it to the last stage.
- `qroots` failures could not be triggered with Si (even `qcut = 0.05`); the pending-`l` rule is covered
  by a synthetic test only.
- Phase 3 (oncvpsp-opt) implemented on 2026-10-14 (uncommitted), opt-in via
  `OncvpspOptimizer(feasibility_mode="by_ell")`; the default `"global"` mode keeps the old single
  `feasible = exit_status == 0` label and classifier. Details:
  - `oncvpsp_opt.optimizer.failure`: `FAILURE_COLUMNS` (`fail_name, fail_stage, fail_scope, fail_ell,
    fail_attribution, fail_params, fail_last_ell, fail_source`), `feasibility_labels` /
    `add_feasibility_labels` (`feasible_attributed`, `feasible_{ell}`, `feasible_global`),
    `failure_from_dict`, `failure_from_exit_status`.
  - `OncvpspOptimizer._failure_as_extra_shim` (like the ecut / nu shims) stores the attributed failure of
    every failed run once as extras of the evaluation work chain: `failure` (the serialized
    `OncvpspFailure`, `None` for a completed run) and `failure_source` (`"output_parameters"` when copied
    from the stored output, `"reparsed"` for legacy runs re-attributed by re-parsing their retrieved
    `oncvpsp.out` (+ stderr) with the current pyoncvpsp, ~12 ms per run). `get_trials_failure` runs the
    shim and reads the extras back; failed runs without extras fall back to `failure_from_exit_status`.
    Re-parsing was chosen over `exit_status_to_stage` because legacy codes >= 513 are ambiguous across
    pyoncvpsp revisions (513 was `wellstate_no_bound_state`, `rxpsh_too_small` or
    `qcut_reduction_failed` depending on the pin) and because it recovers `l` (all 1217 legacy failures in
    `N/PBE/upf/dev/pd06` were attributed to a channel; the 23 legacy 504 runs are completed runs).
    Columns are always joined into `get_trials()`; legacy runs are re-parsed only in `by_ell` mode or with
    `get_trials(reparse_legacy=True)`. The shim was verified read-only first (extras writes patched out
    in the probe) and then run for real on 2026-10-14: the 1240 failed N runs in the dev profile now carry
    `failure` / `failure_source = "reparsed"` extras.
  - Labels: sequential stages (`semilocal`, `vkb`) give 1 for `ell < l` and NaN for `ell > l`; later stages
    give 1 for `ell != l`; `feasible_global` is 0 for `ell_and_local` / `local` / unattributed failures.
  - `fit_feasibility_rfc` fits one RFC per outcome on the channel's active dims (global: all dims), masking
    NaN labels; `models.predict_feasibility` reduces a `ModelList` to `prod_k p_k` (`combine_feasibility`),
    so `initialize`, `generate_candidates*` and `OncvOptProblem` need no changes.
  - Bug fixed on the way: `EnsembleRandomForestClassifier.forward` returned the trees' label-encoded class
    indices instead of the class values (wrong for single-class or non-contiguous class sets).
  - By-ell sampling in `initialize` now records the perturbed channel in the `perturbed_ell` extra
    (`submit(..., perturbed_ells=...)`, `sampled_ells`); `get_trials_input` projects it.
  - oncvpsp-opt now depends on `aiida-oncvpsp` (git pin) and pins pyoncvpsp `e6a3277`.
  - Not done: the pymoo path only uses by-ell sampling for the initial population, so no `perturbed_ell`
    there; `fit_feasibility_gp` remains single-outcome.

12. Agree a machine-readable convention: `ERROR <subroutine>: l=.. iprj=.. : <message>`.
